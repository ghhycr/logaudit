# LogAudit 日志审计平台 · 安装部署手册

> 版本：v1.0（M1~M5 里程碑全量交付） · 适用：Ubuntu 24.04 LTS（x86_64）单机部署
> 部署形态：容器化（Docker Compose），前端静态由 Nginx 托管并反代自研 Go API

---

## 1. 系统架构一览

| 服务 | 容器名 | 镜像 | 端口 | 说明 |
|---|---|---|---|---|
| Nginx | audit-nginx | nginx:1.27-alpine | 80/443 | 静态托管 + API 反代 + TLS |
| API | audit-api | logaudit/api（scratch） | 8080（仅内网） | 自研 Go 后端 + 告警引擎 |
| ClickHouse | audit-clickhouse | clickhouse-server:24.8 | 9000/8123（仅本机） | 日志流水存储（TTL 180 天） |
| MySQL | audit-mysql | mysql:8.0 | 3306（仅本机） | 用户/会话/操作审计/设备台账 |
| Vector | audit-vector | logaudit/vector:0.44.0 | 514 udp/tcp | syslog 实时采集 → ClickHouse |

数据流：`设备(syslog) → Vector(514) → ClickHouse(audit_logs) → AuditAPI → Web(Vue3)`；
操作/元数据：`Web → AuditAPI → MySQL(users/op_audits/devices)`

## 3. 前置准备

### 3.1 安装 Docker

```bash
sudo apt-get update && sudo apt-get install -y docker.io docker-compose-v2
sudo systemctl enable --now docker
sudo usermod -aG docker "$USER"
```

### 3.2 配置镜像源（国内网络必需，实测 Docker Hub 直连会被拒）

```bash
sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": ["https://docker.1ms.run"]
}
EOF
sudo systemctl restart docker
```

> 实测镜像源：`docker.1ms.run` 可用性最好。大镜像（mysql:8.0 约 600MB）可能触发限速，可用下方重试脚本拉取：

```bash
#!/usr/bin/env bash
# pull_retry.sh —— 拉取失败自动重试（最多 10 次，间隔 8s）
img="$1"
for i in $(seq 1 10); do
  docker pull "$img" && break
  echo "[$i] 拉取 $img 失败，8s 后重试..."
  sleep 8
done
```

## 4. 部署步骤

### 4.1 后端静态编译

```bash
cd backend
CGO_ENABLED=0 go build -o ../deploy/docker/api/audit-api .
cd ..
```

> 静态编译（CGO_ENABLED=0）产物可直接进入 scratch 空镜像，规避 alpine 小镜像拉取限速问题。

### 4.2 前端构建

```bash
cd web
npm install --registry=https://registry.npmmirror.com
npm run build:no-type      # 产物 dist/ 由 Nginx 挂载
cd ..
```

> 若宿主机不便安装 Node，可先在任意机器构建 dist 后整体拷贝至 `/opt/audit/web/dist`。

### 4.3 环境变量

创建 `deploy/docker/.env`（可全部省略，使用默认值即可跑通；生产环境必须覆盖）：

```ini
MYSQL_ROOT_PASSWORD=root2026Audit
MYSQL_PASSWORD=audit2026
CLICKHOUSE_PASSWORD=audit2026
JWT_SECRET=change-me-please-9f2c4e1a
ADMIN_INIT_PASSWORD=            # 留空则随机生成并打印至容器日志
```

### 4.4 拉起全部容器

```bash
cd deploy/docker
docker compose up -d --build
docker compose ps               # 等待全部 Up
docker compose restart nginx    # 反代目标 IP 变更后必须执行，否则 502
```

### 4.5 初始化 ClickHouse（仅数据卷非空时需手动执行）

官方镜像首次启动会执行 `clickhouse/init.sql`；若数据卷已存在（重建场景）会跳过 initdb，需手动执行：

```bash
docker exec -i audit-clickhouse clickhouse-client --password audit2026 < clickhouse/init.sql
```

验证表已建：

```bash
docker exec audit-clickhouse clickhouse-client --password audit2026 -q \
  "SELECT count() FROM audit.audit_logs"
```

### 4.6 TLS 证书（自签）

```bash
mkdir -p certs && cd certs
openssl req -x509 -nodes -newkey rsa:2048 -days 3650 \
  -keyout audit.key -out audit.crt \
  -subj "/CN=192.168.143.131" -addext "subjectAltName=IP:192.168.143.131"
```

> 生产环境建议换用 Let's Encrypt 正式证书（DNS 泛解析）。

### 4.7 初始管理员密码

```bash
docker logs audit-api | grep -i password   # 首次启动打印随机初始密码
```

登录 `https://<IP>/` 后立即在「系统设置」修改密码。

## 5. 设备接入指南

### 5.1 Linux 主机（rsyslog → 514）

平台侧「设备台账」先登记设备（名称/IP/厂商/类型），客户端配置：

```bash
# /etc/rsyslog.d/60-audit.conf
*.* @@<平台IP>:514          # TCP 转发（@@）；UDP 用单个 @
# 可选：只转发指定设施
auth,authpriv.*  @@<平台IP>:514

systemctl restart rsyslog
```

### 5.2 网络设备/安全设备

在设备管理界面配置 syslog 服务器为平台 IP:514（华为/思科/华三/H3C 均支持），协议选 UDP 或 TCP。

### 5.3 Windows 主机（Filebeat）

安装 Filebeat，配置输出为 `host: "<平台IP>:5044"`（如需 5044 接入，在 docker-compose.yml 的 vector 服务补充端口映射）。

## 6. 告警规则配置（M5 自研引擎）

「告警规则」页新增规则：

| 参数 | 说明 |
|---|---|
| 规则类型 | frequency（计数阈值）/ spike（基线突增）/ flatline（静默）/ any（命中即告警） |
| 时间窗口 | 秒（<10s 强制 300s） |
| 匹配条件 | host / source_ip / event_type / 关键词 / 最低级别 |
| 分组聚合 | 按 host / source_ip / event_type / user_name 独立判定 |
| realert 去重 | 同规则+维度窗口内只告警一次 |
| 动作 | Webhook（POST JSON 含命中样本）/ SMTP / 平台内事件记录 |
| 试运行 | 保存前可 dry-run 测试命中 |

演示规则示例（SSH 暴力破解）：

```json
{
  "name": "SSH暴力破解高频告警",
  "rule_type": "frequency",
  "window_seconds": 60,
  "threshold": 2,
  "query_filter": { "event_type": "ssh_bruteforce" },
  "group_by": "host",
  "realert_seconds": 60,
  "severity": "high",
  "actions": [{ "type": "webhook", "url": "https://hook.example.com/alert" }]
}
```

## 9. 常见问题排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 页面 502 Bad Gateway | nginx 容器重建后反代目标 IP 过期 | `docker compose restart nginx` |
| 后端容器反复重启 | MySQL 未就绪 | 等待 mysql healthy 后 `docker compose up -d api` |
| 镜像拉取失败/超时 | Docker Hub 直连被拒 | 配置 `docker.1ms.run` 镜像源 + 重试脚本 |
| 小镜像（alpine）拉取卡死 | 镜像源限速 | 后端改用 scratch 空镜像（CGO_ENABLED=0） |
| ClickHouse 表不存在 | 数据卷非空跳过 initdb | 手动执行 `clickhouse/init.sql` |
| `ngrambf_v1` 建表报错 | 24.8 需 4 参数 | `ngrambf_v1(3, 3072, 2, 0)` |
| 修改后端后 502 | 二进制未重新编译 | 重编译 → `docker compose up -d --build api` → 重启 nginx |
| 告警未触发 | realert 窗口内去重 / 引擎节流 | 检查规则 run_interval（<10s 强制 60s）、窗口（<10s 强制 300s） |
| 前端更新不生效 | 浏览器缓存 | Ctrl+F5 强刷（index.html 已配 no-cache） |

## 11. 安全说明（等保三级）

- 数据库端口仅绑定 127.0.0.1，不对外暴露
- Nginx 输出完整安全响应头（CSP / X-Frame-Options / nosniff / Referrer-Policy）
- JWT 双令牌 + CSRF 双校验 + 账号锁定 + 操作审计全留痕
- 日志保留 180 天（可配），到期 ClickHouse TTL 自动清理
- 生产部署必须：更换默认密码、JWT_SECRET、启用正式证书
